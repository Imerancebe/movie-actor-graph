选题调研 · 背景与意义

电影合作数据，天然是一张大规模图

  • ① 数据基础成熟

    IMDb 官方公开数据集沉淀千万级「演员—电影」出演记录：演员与电影为节点、出演为边、同片出演派生演员合作关系，天然构成大规模属性图，无需人工构造。

  • ② 业务问题真实

    谁是影史最具影响力的演员（影响力排名）？电影圈存在哪些合作圈子（社区发现）？两位演员通过几部电影相连（合作路径）？——全部是图挖掘的经典问题域。

  • ③ 技术覆盖完整

    选题完整覆盖「大数据底层处理 → 图数据存储与挖掘 → Web 业务应用」三层课程考察环节，与课程四层架构一一对应，且包含 PageRank、LPA 等算法深度，不是纯增删改查系统。

为什么选电影演员关系：一是数据现成且天然成图；二是能提出影响力、社区、路径这些真实的图分析问题；三是技术栈覆盖课程要求的完整链路，且算法有深度。

对比了三类候选数据源：MovieLens 只有评分没有演员关系，豆瓣无官方开放数据。IMDb 三个文件正好构成演员-电影-出演三元组，官方公开合规，所以选定 IMDb。

实施方案 · 图模型

属性图模型与数据圈定策略

属性图模型（Neo4j）

  • Actor 节点：id / name / birthYear + 挖掘属性 pagerank · community · degree
  • Movie 节点：id / title / year / runtime / genres
  • ACTED_IN：演员 → 电影（职务、主演排序）
  • CO_ACTOR：演员 ↔ 演员（weight = 合作电影数）
  • 索引：id 唯一约束 · name 索引（搜索）· community 索引（过滤）

圈定策略（达到大数据规模）

  • IMDb 全量 1,400 万作品 → 按评分人数降序取 Top 2,500 部
  • 每部电影取 principals 排序前 15 位主演（防边组合爆炸）
  • 由出演记录反推演员集合，保证无孤立节点
  • 参数集中在管道配置，规模不足可调参重跑
  • 规模目标：节点 ≥ 10,000 · 边 ≥ 30,000（课程硬性门槛）
左边是图模型：两类节点两种边，挖掘指标作为节点属性回写。右边讲规模怎么来：全量太大，按热度圈定 Top 2500 电影、每片 15 位主演，反推演员集合，参数可调。

实施方案 · 算法

三大图挖掘算法：Spark RDD 自主实现

加权 PageRank

演员影响力
PR(v) = (1−d)/N + d·Σ PR(u)·w(u,v)/W(u)
d = 0.85

合作网络视为无向加权图，合作越多传递声望越高。RDD join + reduceByKey 迭代；预分区 + 分区器继承，每轮仅 1 次 shuffle。收敛条件 Σ|ΔPR| < 1e-5 或 15 轮上限。

标签传播 LPA

合作社区发现
label(v) ← argmaxl Σu∈N(v) w(u,v)·[label(u)=l]
平局取最小 id · min 单调收敛

每轮取邻居边权加权票数最多的标签，新旧标签取 min 保证收敛，12 轮上限。复杂度近线性，适合 10 万级边；比 Louvain 实现简单、可解释，适合课设周期。

Adamic-Adar + Jaccard

合作链路预测
score(u,v) = Σw∈N(u)∩N(v) 1/√deg(w)
+ Jaccard 相似度

对「合作者的合作者」打分，弱连接的共同邻居权重更高；过滤已有合作关系，输出 Top-N 潜在合作者及共同合作者证据 —— 推荐结果可解释。

三个核心算法都在 Spark RDD 上手写：PageRank 处理影响力，关键是每轮只做一次 shuffle；LPA 做社区发现，用 min 保证单调收敛；Adamic-Adar 做合作预测，输出共同合作者作为证据，可解释性强。

实施方案 · 接口与交互

12 个 REST API 与交互式可视化

业务逻辑层 · API

  • 图查询：stats / overview / neighbors / detail / path
  • 榜单：rank/pagerank · rank/degree（Top-N）
  • 挖掘结果：communities / community members / predict
  • 搜索：actor/search 前缀优先，响应 ≤ 500ms
  • 统一响应 {code, msg, data} + OpenAPI 自文档
  • 性能指标：2 跳图查询 ≤ 2s · 列表搜索 ≤ 500ms

交互层 · 可视化映射

  • 力导向图：节点大小 = pagerank（对数 8~46px）
  • 社区着色：颜色 = LPA 社区编号（20 色循环）
  • 边映射：粗细/透明度 = 合作电影数
  • 点击节点 → 邻域聚焦 + 详情抽屉（电影/合作者/预测）
  • 路径查询 → 序号链路高亮 · 社区点击 → 子图过滤
  • 首屏采样 ≤ 500 核心节点，保证流畅渲染
后端 12 个接口覆盖图查询、榜单、挖掘结果、搜索四组；前端把数据映射到视觉通道：大小是影响力、颜色是社区、边粗细是合作强度。点击、路径、社区过滤三类交互全部落实。
